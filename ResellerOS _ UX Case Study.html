1. Executive summary and scorecard

ResellerOS is a web app for people who sell second-hand goods online. It helps a seller create a listing quickly with AI, track the real profit on every item after costs and platform fees, and see which stock has gone stale and needs a price drop. The design covers a starter (landing) page, log-in, sign-up, PIN authentication, forgotten password, an Overview dashboard, New Listing, Profit Tracker, Stock Watchlist and a log-out confirmation.

This is the cleanest and most professional of the four projects: a dark green sidebar, warm cream canvas and gold accent give it a calm, financial-tool feel, and the landing page uses an original dashboard illustration instead of stock images. I have not reviewed earlier versions of this project in this conversation, so the assessment covers the current state.

Its biggest advantage is that it is a real, working product with a clear market. Its biggest weakness is accessibility of colour and text size: the gold form labels sample at about 2.5:1 on white, and tables and body text are very small.

1.1 What has improved

  • A focused landing page: a strong headline, clear calls to action, a dashboard preview drawn for the product, a 'How it works' row and a 'Sellers using it' testimonial row.

  • Consistent application layout: dark sidebar with Overview, New Listing, Profit Tracker and Watchlist, and a cream content canvas.

  • Authentication set is complete and consistent: log in, sign up, PIN and forgotten password share the same card layout and dark primary buttons.

  • Clear primary actions: dark buttons on cream and gold 'Mark Sold' and 'Yes / No' buttons with dark text (excellent contrast).

  • Real product logic: cost price, condition, platform, generated listing, previous listings, sold status and price-drop suggestions.

3. Problem, solution and benefit

3.1 Problem

Reselling is a mainstream side income. A Royal Mail poll of 1,000 people with an online side hustle found an average of about GBP 452 a month, and second-hand fashion in the UK is worth more than GBP 7 billion. Yet sellers usually work with a notebook or spreadsheet, write each listing by hand, and only discover after weeks that an item has not sold or that fees and postage erased the profit.

The pain is threefold: slow listing creation, unclear real profit, and stale stock that nobody is watching.

3.2 Solution

ResellerOS puts all three in one place. New Listing takes an optional photo and a few facts (item name, condition, cost price, platform) and the AI generates a listing. Profit Tracker shows active listings with a Mark Sold action that records the sale and calculates profit. Watchlist flags items that have been listed too long and suggests a price drop. Overview summarises listings, profit and items that need attention.

3.3 Benefit

  • Saves time: AI-generated listings in seconds instead of minutes.

  • Shows real profit after cost and fees, so sellers price and source better.

  • Reduces dead stock with proactive price-drop suggestions.

  • One calm dashboard replaces spreadsheets and scattered notes.

  • Helps sellers keep records for their own accounts and tax needs.

6. User stories and acceptance criteria

ID

User story

Acceptance criteria (Given / When / Then)

US-01

As a seller, I want to sign up, log in with a PIN and reset a forgotten password so that my data is private.

- Given I am new, when I complete username, email, password and confirmation, then my account is created.

- Given I forgot my password, when I enter a new matching password, then I can log in.

- Given I enter a wrong PIN, then I see a clear message and can request a new code.

US-02

As a seller, I want to create a listing from a few facts so that I list faster.

- Given I enter item name, condition, cost price and platform, when I choose Generate listing, then an editable draft appears within 10 seconds.

- Given a photo is optional, when I skip it, then the draft still generates.

US-03

As a seller, I want to edit and publish the draft so that I stay in control of what is posted.

- Given a draft, when I edit any field, then my changes are saved.

- Given I confirm, then the listing is saved as Active.

US-04

As a seller, I want to mark an item sold and see profit so that I know what I earned.

- Given an active listing, when I choose Mark Sold and enter the sale price, then profit is calculated from cost, fees and sale price.

- Given the sale is saved, then Overview totals update.

US-05

As a seller, I want a watchlist of stale items so that I act on them.

- Given an item has been listed longer than my threshold, then it appears on the Watchlist with a suggested price and reason.

- Given I accept, then the price is updated.

US-06

As a seller, I want an overview so that I can see profit and items needing attention at a glance.

- Given I open Overview, then I see key figures, a profit chart and items needing a price drop.

US-07

As a seller, I want previous listings so that I can reuse or review them.

- Given New Listing, then previous listings are shown with date, item and outcome.

US-08

As a user with access needs, I want readable text, labelled fields and keyboard use so that I can work independently.

- Given any form, then each field has a visible label, and errors are described in text.

- Given browser zoom at 200%, then content reflows without horizontal scrolling.

- Given a keyboard, then all actions are reachable and show focus.

11. Technical documentation

11.1 Architecture and recommended stack

A React front end talks to a Python (FastAPI) API. The API stores users, items, listings and sales in a relational database. A listing service calls an LLM with a structured prompt (item name, condition, platform, tone) and returns an editable draft. A profit service calculates profit as sale price minus cost, platform fees and postage. A scheduled job flags items listed longer than a threshold and creates price suggestions.

11.4 Software development life cycle (SDLC) recommendation

Recommended model: Agile using Scrum-lite or Kanban with continuous integration and delivery, and Lean Startup validation loops.

Why this model fits

  • It is a live product that can gain real users, so frequent small releases and quick fixes matter.

  • The AI feature needs constant prompt and quality iteration based on user edits.

  • A hackathon prototype carries technical debt; short iterations let the team schedule a hardening sprint without stopping delivery.

  • Solo or small team: Kanban limits work in progress and keeps focus.

  • Lean Startup metrics (activation, retention, draft acceptance) tell the team what to build next.

12. Design system

12.1 Colour theory

The palette is built on a near-black green (#16211D), warm cream (#F4F0E4), white, a muted leaf green (#3F7D58) and a mustard gold (#C8A127). Dark green reads as money, growth and stability; cream is warm and paper-like, which suits a tool people stare at for a long time; gold signals value and reward.

This is an analogous scheme (green with a yellow-green gold) balanced by neutrals, close to the 60-30-10 rule: about 60% cream and white, 30% dark green in the sidebar and headers, and 10% gold and green accents.

Contrast roles matter: gold works as a fill with dark text (6.8:1) or as an accent on the dark sidebar (6.8:1), but not as text on white or cream (2.5:1 and 2.2:1). The current gold form labels should become dark text with a gold underline or icon.

12.5 Styling strategies

  • Design tokens for colour, type and spacing so the Figma kit and the code stay in sync.

  • Dark navigation, light workspace: the sidebar frames the tool and the cream canvas keeps forms and tables easy to read.

  • One primary action per screen: dark buttons for confirm, gold for celebratory or high-value actions such as Mark Sold.

  • Progressive disclosure: summary cards first, detail tables on demand.

  • Trust cues: testimonials, 'How it works', clear log-out confirmation.

  • Inline validation and plain-language errors for money and PIN fields.

12.6 Design structure and layout

  • Public: Starter page with hero, dashboard preview, How it works, Sellers using it and a dark closing call to action.

  • Authentication: centred card on cream with logo, form and a link to switch between Log in and Sign up.

  • App: fixed dark sidebar (Overview, New Listing, Profit Tracker, Watchlist, account and log out) and a main content area with a title and a primary action at top right.

  • Grid: 8-point spacing; cards with consistent radius and padding.

12.7 Components, iconography and imagery

  • Buttons: dark primary, gold accent with dark text, outlined secondary.

  • Forms: labelled inputs with icons, visible focus, inline validation.

  • Tables and cards: striped rows, right-aligned numbers, status chips with text.

  • Imagery: original dashboard illustration and icon set; no stock photos.


13. WCAG 2.2 accessibility audit

Short answer: not yet fully compliant, and a design cannot be certified; a built web app must be tested with a keyboard and screen reader. The structure is good. The main known failures are gold text labels and very small table text.

For a web product, reflow at 200% zoom, keyboard operation, form labelling and status messages are as important as colour.

Target: WCAG 2.2 Level AA (the current W3C Recommendation since 5 October 2023). Statuses: Likely pass, Needs test, Likely fail (fix), Not verifiable in a static design.
